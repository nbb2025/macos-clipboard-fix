# 排查过程与实现边界

这次故障表现为：iPhone/iPad 可以复制到 Mac，但在手机粘贴 Mac 新复制的内容时，总是旧内容或空白。

下列步骤按实际排查顺序整理。前几项单独执行后未恢复；最后备份旧发送缓存、重新加载服务并用新文字复测后，实际跨设备粘贴恢复。它说明此流程适合这一类故障，不代表所有通用剪贴板问题都有相同原因。

| 步骤 | 当时的观察 | GUI 对应功能 |
| --- | --- | --- |
| 核对方向与基础条件 | Mac 能接收，发送异常；接力、Wi-Fi、蓝牙、附近连接已开启 | 连接概览、故障方向选择 |
| 重启接力与设备发现 | 仍然粘出旧内容 | 温和修复、刷新设备发现 |
| 刷新身份与本机剪贴板 | 单独执行未解决 | 刷新设备身份 |
| Mac 与手机重新启用接力 | 仍然失败 | 重新启用接力、手机设置说明 |
| 蓝牙关闭再开启 | 未恢复，手机一度粘贴空白 | 蓝牙设置入口；由使用者手动切换 |
| 使用明确的新纯文字 | 核对 Mac 中确实是测试码后，手机仍收到空白 | 生成测试文字、核对本机内容 |
| 暂停代理 TUN 做对照 | 使用者测试后仍失败，不能据此归因代理 | 只读代理状态、手动对照指南与恢复提醒 |
| 比较缓存元数据 | 发送缓存较旧，接收缓存仍在更新；这是线索，不是独立的故障证明 | 发送/接收缓存时间、大小、诊断建议 |
| 保留旧发送缓存并重新加载服务 | 随后实际跨设备粘贴恢复，系统自行生成新缓存 | 重建发送缓存、可恢复备份、跨设备复测 |

## 为什么保留旧文件

缓存位于当前用户的 `Library/Group Containers/group.com.apple.coreservices.useractivityd/shared-pasteboard`。程序只接受该目录下系统登记的 UUID 文件名，通过重命名保留旧文件，不读取文件正文。正常移动采用禁止覆盖的原子重命名；遇到 macOS 隐私保护时，使用固定访达脚本，路径通过参数传入。

操作前先写入恢复登记，文件移动后再确认备份存在。恢复时同样先保护原位置的新文件。登记保存在应用自己的私有目录中，重新打开应用后仍可找到程序创建的备份。此前在程序外手工改名的文件不会自动导入。

重建时不删除 `kLocalPasteboardBlobName` / `kRemotePasteboardBlobName` 偏好键，也不提前伪造新缓存。系统可能在后续共享时才更新指针和生成文件；请用新的测试文字执行实际粘贴。

## 哪些现象不能当作成功

- 服务出现新 PID，只证明进程已重新加载。
- 基础条件全为绿色，只证明本机检查项已满足。
- 缓存时间变化，只证明有文件活动。
- 本机 `pbpaste` 返回测试码，只证明本机写入正确。

只有另一台设备实际粘贴出同一段新文字，并由使用者确认，界面才记录该方向成功。重新生成测试码或执行新的修复会清除本轮成功标记。

## 日志与高级排查

「采样接力日志」检查最近三分钟与 useractivityd、sharingd、rapportd 相关的有限日志，返回包装密钥重试、数据提供方和请求方等计数。密钥重试可能只是旁证，不能仅凭一条日志断定根因。应用不显示或导出原始系统日志。

Maccy / Snipaste 可临时退出对照；应用不会修改它们的历史数据库。代理对照完全手动：先记录原设置，暂时关闭 TUN，复测，再恢复。90 秒计时只提醒，不会自动修改或恢复网络。

应用不会自动退出 Apple 账户、删除钥匙串、清空系统配置或要求重装系统。若基础检查和上述可恢复步骤仍未解决，可以先分别重启设备，再参考 [Apple 通用剪贴板说明](https://support.apple.com/102430) 核对兼容条件。
